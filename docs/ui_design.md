# 中文界面与产品设计取舍

2026-10-12：将原来的英文操作界面改为中文，并简化信息层级。欧美女性听众和英文有声剧的内容定位保持一致；英文剧本与生产指令保留原文。

## 设计目标

让首次体验者能回答三个问题：我需要提供什么，Agent 会产出什么，如何判断和改进质量。产品围绕“创作需求 → Agent 协作 → 质量评测 → 数据反馈”组织，而非把技术细节作为默认入口。

| 设计调整 | 对应的产品思路 |
| --- | --- |
| 主导航突出总览、工作流、评测，另两页收进更多工具 | 优先呈现内容生产与质量改进的主路径，降低首次体验的选择负担 |
| 工作流明确“选择需求 → 运行 → 查看并优化” | 用可完成的任务引导使用，而非只展示复杂流程图 |
| 六个 Agent 按编号顺序导航 | 保持 AI 协作分工，同时让执行关系容易理解 |
| 每步说明任务、输入和验收标准 | 展示业务问题如何转化成 Agent 责任与质量要求 |
| 默认中文成果卡片，结构化数据折叠 | 优先让用户判断内容是否有用；技术数据仍可检查和导出 |
| Story Bible 显示人物事实和一致性约束 | 将“避免人物漂移”落实为对后续生成的明确约束 |
| 评测案例先展示证据、原因和优化方式 | 问题必须可定位、改进必须可执行，避免只有一个总分 |
| 英文指令编辑收进详情，仍可自由修改 | 降低第一次操作门槛，同时保留可审核、可迭代的提示词 |
| 完成后引导进入质量评测 | 内容生成完成不等于可以发布，人工审核是制作前的决策边界 |
| 实验页展示假设、变量、指标和下一步 | 区分指标观察与因果验证，让数据返回下一轮创作策略 |

## 保留的能力

六阶段顺序运行、取消与重试、中文项目创建、双语搜索、项目切换、四维质量指标、Prompt 优化与模拟重新评测、跨页反馈、浏览器持久化、CSV/JSON 导出均可操作。

不迁移或重置已有浏览器数据。展示文案与内部状态分离，原项目、问题编号和 Prompt 版本仍可恢复。

## 演示边界

Agent 与评测使用 Mock 数据，音频步骤生成制作计划，实验值仅为示例。中文界面解释产品流程，不能据此声称已经接入真实模型、生成真实音频或取得业务增长。
